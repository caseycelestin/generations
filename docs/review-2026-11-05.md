# Code review, 2026-11-05

A review pass over `main` at `fb7121d` (after PR #18, the end of the step 4
device work). Clippy, `cargo test` (79 passed, 1 ignored) and `cargo doc`
with `-D warnings` were all green, so every finding is semantic. Nothing
here has been changed yet; tick items off as they are tackled.

**Delete this file once every item is addressed.** It is a working list,
not a record; anything worth keeping belongs in the roadmap or the code.

Ranked most severe first.

## 1. `Engine::open` hard-requires an output device

`src/engine.rs:52`. `Engine::open` is now the only public constructor and
it calls `Device::default_output()`, so any headless use (CI, the
`first_print` example, a CM4 before the DAC is wired, an ssh session with
no sound server) fails with `DeviceError::NoOutputDevice` where it used to
work. `lib.rs` no longer exports `Storage`, `FileStorage` or `ResidentSet`
and `Engine::on` is `pub(crate)`, so there is no device-less path left
outside the crate.

- [ ] decide: a device-less constructor, or an `Engine::open` that defers
      the device until `play`

## 2. `default_output()` refuses non-F32 devices

`src/device.rs:59`. The config filter only accepts formats the backend
reports natively as F32. cpal does no sample-format conversion, and the
ALSA host enumerates only what `hw_params.test_format` accepts, so a raw
`hw:` I2S DAC (typical on the CM4 target) that is S16/S32-only matches
nothing and returns `UnsupportedFormat { rate: 48000, channels: 2 }` even
though it runs 48 kHz stereo fine. The roadmap commits to refusing on rate
mismatch; refusing on format is an extra, undocumented hard failure on the
target hardware.

- [ ] accept I16/I32 configs and convert f32 to the device format in the
      callback, or open via a `plughw`/default plug so ALSA converts

## 3. A failed open still creates the project on disk

`src/engine.rs:53`. `storage::open(dir)` runs before
`Device::default_output()`, so on a device-less machine the directory and
manifest are created and fsynced, then the device check fails and the
caller gets `Err`. A typo'd path leaves a stray valid project behind. The
device needs nothing from the project.

- [ ] open the device first, or open storage only after the stream is up

## 4. CI installs `libasound2-dev` without `apt-get update`

`.github/workflows/ci.yml:31` and `:41`. GitHub's Ubuntu images ship a
stale package index. When Ubuntu publishes a rebuild of the package the
cached index points at a superseded `.deb`, `apt-get install` 404s, and
both the clippy and test jobs go red on an unrelated PR. `main` is
protected on green CI.

- [ ] `sudo apt-get update && sudo apt-get install -y libasound2-dev`

## 5. `eprintln!` in the stream error callback

`src/device.rs:90`. The error callback runs on the audio thread and takes
the stderr lock, which may block or allocate, exactly when an xrun or
device removal is being reported. If the control thread holds stderr the
audio thread misses its deadline and causes further xruns: a feedback loop
on the event being reported. The roadmap defers *where* errors go, but
this is the one place the PR adds blocking work to the real-time path.

- [ ] replace with a lock-free flag (`AtomicBool`, or a second `rtrb`
      ring) that the control side reads

## 6. `stream` drops after the control half of `Engine`

`src/engine.rs:41`. Fields drop in declaration order and `stream` is
last, so on `drop(engine)` the `project` and `playback` (command producer
and `ResidentSet`) go first while the audio thread is still rendering.
Voices still ringing become the last `Arc` holders and the buffer frees on
the audio thread, the hazard the roadmap lists as a rule to keep, and the
renderer pops from an abandoned ring for a few periods. Safe today only
because of `Arc`.

- [ ] declare `stream` first so the thread stops before the control half
      goes

## 7. Redundant `BufferSize::Default` override

`src/device.rs:68`. `StreamConfig { buffer_size: BufferSize::Default,
..supported.config() }` is a no-op: cpal 0.18's
`SupportedStreamConfig::config()` already sets `BufferSize::Default`. The
struct update reads as a deliberate period-size choice that is not being
made.

- [ ] `let config = supported.config();`, which is also where a future
      `BufferSize::Fixed(n)` for the Pi would go

## 8. `Option<Stream>` is a test-only shape in the public type

`src/engine.rs:38`. The `None` arm exists only so tests can build an engine
without a device; production never produces it. Future code that needs the
stream (restart after device loss, query the period size) has to handle a
`None` that cannot happen.

- [ ] pass the driver into `Engine::on`, or keep the stream outside
      `Engine` in `open`'s caller, so the seam lives in test-facing code

## 9. `Playback::play` burns a `VoiceId` on `CommandsFull`

`src/playback/control.rs:54`. `next_voice` increments before `send()` is
known to succeed, so a full ring returns `Err(CommandsFull)` with the id
already consumed. Harmless today (ids are never reused and `u64` does not
run out), but a refused press and an accepted one become indistinguishable
in the id sequence, which a future event log or front panel replaying ids
would trip on.

- [x] build the `Command` first and bump `next_voice` only on `Ok` (PR 21)

## Checked and dropped

- `Engine` becoming `!Send` via `cpal::Stream` is not a regression:
  `Storage` has no `Send` bound.
