## 2. `default_output()` refuses non-F32 devices

`examples/device/mod.rs` (was `src/device.rs:59`; the device left the library in PR 23). The config filter only accepts formats the backend
reports natively as F32. cpal does no sample-format conversion, and the
ALSA host enumerates only what `hw_params.test_format` accepts, so a raw
`hw:` I2S DAC (typical on the CM4 target) that is S16/S32-only matches
nothing and returns `UnsupportedFormat { rate: 48000, channels: 2 }` even
though it runs 48 kHz stereo fine. The roadmap commits to refusing on rate
mismatch; refusing on format is an extra, undocumented hard failure on the
target hardware.

- [ ] accept I16/I32 configs and convert f32 to the device format in the
      callback, or open via a `plughw`/default plug so ALSA converts

## 4. CI installs `libasound2-dev` without `apt-get update`

`.github/workflows/ci.yml:31` and `:41`. GitHub's Ubuntu images ship a
stale package index. When Ubuntu publishes a rebuild of the package the
cached index points at a superseded `.deb`, `apt-get install` 404s, and
both the clippy and test jobs go red on an unrelated PR. `main` is
protected on green CI.

- [ ] `sudo apt-get update && sudo apt-get install -y libasound2-dev`

## 5. `eprintln!` in the stream error callback

`examples/device/mod.rs` (was `src/device.rs:90`). The error callback runs on the audio thread and takes
the stderr lock, which may block or allocate, exactly when an xrun or
device removal is being reported. If the control thread holds stderr the
audio thread misses its deadline and causes further xruns: a feedback loop
on the event being reported. The roadmap defers *where* errors go, but
this is the one place the PR adds blocking work to the real-time path.

- [ ] replace with a lock-free flag (`AtomicBool`, or a second `rtrb`
      ring) that the control side reads

## 7. Redundant `BufferSize::Default` override

`examples/device/mod.rs` (was `src/device.rs:68`). `StreamConfig { buffer_size: BufferSize::Default,
..supported.config() }` is a no-op: cpal 0.18's
`SupportedStreamConfig::config()` already sets `BufferSize::Default`. The
struct update reads as a deliberate period-size choice that is not being
made.

- [ ] `let config = supported.config();`, which is also where a future
      `BufferSize::Fixed(n)` for the Pi would go
